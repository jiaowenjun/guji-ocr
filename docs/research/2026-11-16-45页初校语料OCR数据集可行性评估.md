# 45 页初校语料生成版式与文字 OCR 数据集的可行性

评估日期：2026-11-16。对象：康熙字典武英殿版 @312–358，不含 329、337，共 45 页。依据当前文件、生产解析／布局代码、字体字形检查及原图抽查；本次没有训练模型或生成完整训练集，也没有重新逐字终校。

**结论：两种方案均可行，建议建立同源的真实扫描集与合成渲染集。方案 1 是真实扫描识别的评测依据；方案 2 是自动获取文字、版式坐标与阅读顺序监督的低成本入口。45 页足以启动开发集和专项微调实验，不能支撑通用古籍 OCR 的性能结论。**

机器证据：[本次核查结果](evidence/2026-11-16-ocr-dataset-feasibility.json)。已有基础：[排版数据结构与算法评估](2026-11-16-古籍排版数据结构与算法评估.md)、[数据集说明](../../kangxi-gold/README.md)。

## 2. 两种输入方案的适用范围

| 任务 | 方案 1：原扫描图 | 方案 2：`.gj` 渲染图 |
| --- | --- | --- |
| 整页图 → 正文文本 | 已有图片和 TXT，可立即组织开发数据 | 可以生成；图中文字应来自与标签一致的 profile |
| 整页图 → 规范化结构化转写 | 可用 `.gj／IR` 作为初校级目标，仍需抽查版面对应 | 更容易形成严格配对的合成样本 |
| 大小字、列片段、书名框、圈号定位 | 缺少经过复核的原图坐标，需要补定位 | 布局已有字格位置，可自动导出合成图坐标；导出器尚需实现 |
| 阅读顺序监督 | IR 提供转写序；补坐标后可做区域排序 | IR／布局计划提供顺序，可直接挂到合成区域 |
| 真实扫描的字形、噪声与缺损 | 保留，最接近实际使用条件 | 缺少，需增加退化扰动及真实样本适配 |
| 扩充数量 | 目前 45 个来源页，可进一步补页 | 可变分辨率、背景、模糊等；独立内容仍只有 45 页 |
| 首版实施成本 | 纯文本低；精确定位较高，人工复核为主 | 中低，主要是导出器、像素坐标及标签验收 |
| 推荐角色 | 真实开发／验证集；终校后构成受控测试子集 | 训练辅助、结构恢复实验、导出链路回归 |

“版式识别”需要明确任务定义：若输出是列层级、字号、折行、阅读顺序的结构化转写，并不强制要求 bbox；若要训练检测器或评测 IoU／mAP，则必须有对应输入图的几何标注。原图方案目前具备前一种数据的基础，后一种还没有完成。

## 3. 方案 1：原图方案还缺什么

### 3.1 文字与版面结构可以先使用

现有 `.gj／IR` 已提供人工修订的文字、大小字、局部折行、空位、标题层级、书名和圈号。可以整理成 `scan → text`，或 `scan → canonical structure` 的开发样本。

原书未呈现的编辑标点不应作为严格视觉 OCR 的必答字符：当前 IR 原文含标点，渲染和 TXT 会按 `meta.profile` 清洗。若目标是输出 `.gj`，应先定义规范化写法，以保留可见文字与结构；标点恢复可以单列任务。无需要求模型复原源码中等价的语法糖、注释及空行写法。

### 3.2 渲染坐标不能复制成原图标注

`layout3` 给出的是规范字格；预览页的 `SCAN_FRAME_MARGIN` 是共享的版框适配参数。字体宽度、刻本字距、页面裁切及局部位置并不因此成为原图真值。本次在浏览器对照 @312、@328，可见扫描与合成页面的字形、纹理及横向位置不同。

已有 `tools/eval/kangxi_column_seg.py` 可以辅助起草原图列界。本次只读运行 @312、@328、@334、@349、@351，均得到候选结果，17 条网格界中有谷值支持的数量为 10、10、15、13、9；其 8 大列／16 小列数量来自预设，不能解释为检测准确率。脚本也没有产出经人工确认的逐字标签。

建议流程：逐页确认正文区域 → 初始化 8 个 band → 按原图调整各 band 和局部大小字片段 → 将 IR 文本与片段对齐 → 复核框线、圈号及阅读序。字符级框可作为后续精化，不必阻塞第一版区域／列片段数据集。局部尺寸差异应通过各区域修正，必要时再引入形变配准。

### 3.3 未转写区域必须有明确口径

当前标签不包含版心、鱼尾、边框、印章和页脚水印。整页原图中这些内容可能可见。应选择并记录：只识别指定正文区域，或完整输入并对非目标区域给出 `ignore`；若目标变为全页全部文字，则补齐相关转写。不能把可见但未标注的文字默认当成检测背景。

现有 CER 脚本会把读出的水印计作插入，属于现有整页协议；新增正文区域评测应另行命名，不能在结果中静默更换口径。

## 4. 方案 2：合成数据的价值与导出约束

### 4.1 可以自动得到多层监督

建议从同一份 IR／布局计划同时导出 PNG 与标签，保留以下信息：页面、band、局部小字 run、大字／合字格、文字、父子关系、阅读序、书名片段链接、圈号及源位置引用。裁剪大列、run 和字格时同时记录裁剪变换。

首版可形成 45 张干净整页图、最多 352 个有内容的大列裁剪、947 个小字片段裁剪及 275 个大字格裁剪。它们相互嵌套，不能相加宣称为相同数量的独立样本。

坐标需要显式注明是 **字格占位框、文字墨迹框还是装饰框**。`layout3` 可直接支持字格框；DOM 的 `getBoundingClientRect()` 也是元素框，不会自动变成紧贴笔画的字形框。若需墨迹掩码／紧框，应增加单独字形渲染或掩码导出。

### 4.2 必须处理的具体问题

1. **按 IR／布局计划导出阅读序。** 本次 `planLayoutBand` 顺序与 TXT 在 45/45 页一致；按 `band.items` 线性串接则有 41/45 页不一致。原因是布局结果先收集大字、后收集小字，`MatrixPages` 也按此顺序生成 DOM。截图的空间位置正确，不代表 `innerText/textContent` 的顺序适合当 OCR 标签。
2. **按最终像素空间导出位置。** 包括水平／垂直字格尺寸、纸边、边框、26 个半格偏移 run、截图裁剪和设备像素比例；圈内合字还有 CSS 压缩。变形增强必须同步变换框或多边形。
3. **只截取稳定的出版内容。** 去掉编辑高亮、页码 UI、鼠标悬浮、警告与工具栏；明确是否保留页框。原扫描本无内部界栏，基础样本应保持界栏关闭，额外界栏样式单独作为变体。
4. **确认字体真正加载。** 当前 CSS 使用 `font-display: swap`，导出应等待目标字体加载并验证，避免截图捕获回退字体；同时确认页码、图像与布局已切换到同一页，页面采用异步加载／防抖。
5. **保留合字、空位与标注层。** 四个合字采用一个单元对应多个码点；326 个空白字格是排版证据，不输出为文字检测目标；书名框与圈线作为独立装饰／关系，避免被当成额外正文字符。
6. **从当前 v3 主路径取标签。** 不沿用旧解析器的纯文本输出；现有审计已发现 8 页与旧解析器口径不同。

### 4.3 字体覆盖已经满足当前语料的基本要求

本次按实际大小字字体栈检查 cmap，并对每个使用码点检查非空轮廓：279 个大字码点实例、14,987 个小字码点实例全部有字形，无缺字或空轮廓；正文没有 `□` 或替换字符 `�`。这说明无需为当前语料大规模补字体，不能说明每个字形都与原刻完全一致。

两个 PUA 码点应随数据发布稳定映射：@342 的 U+E815 出现 2 次，@349 的 U+E701 出现 1 次。项目登记簿已有 E701；E815 也应在导出字形表中补充来源、图样、含义／身份依据。UTF-8、Unicode 码点索引与源码 UTF-16 偏移必须分开；不要自动做繁简转换或 NFKC 归一化。

### 4.4 合成图的效果边界

当前小字主要来自中华书局宋体，大字来自康熙字典字体；背景和笔画远比原图规整。因此，合成集很适合验证大小字混排、框线干扰及阅读顺序，但其识别成绩不能代替扫描图成绩。

可增加模糊、降采样、压缩、墨色变化、纸纹、小幅倾斜与局部几何扰动。参数应参照真实扫描分布。仅对 45 页反复换背景不能带来新的字种、词条或版式，更不能预先保证微调提高真实 OCR 准确率。

## 5. 推荐标签和数据划分

建议保留三层：

- **转写源**：`.gj` 与 IR、清洗 profile、初校／终校状态、内容哈希。
- **图像视图**：`scan` 或 `synthetic`、来源页 ID、图片哈希、宽高、裁剪／增强变换、渲染器和字体版本。
- **图像标注**：region／run／glyph 的 bbox 或 polygon、坐标类型、文字、字号、阅读序、parent／source 引用、overlay 关系及 ignore 区域。

原图与合成图共用文字来源，但各自保存几何；严禁把二者 bbox 放入同一坐标系。内部规范可用 JSON；按下游需要派生 PAGE XML（位置、转写、阅读序）、COCO（区域检测）、图像路径与文字对（识别），或图像到结构化目标的训练样本。

标签应区分可见字号与语义角色：`small` 不自动等于夹注，`large` 不自动等于词条字头。当前语料支持本书的字号与部分结构分类，没有覆盖通用古籍的眉批、侧批、图表等完整语义类别。

**先分来源，再裁剪与增强。** 同一页的原图、渲染图、所有裁剪与增强必须在同一集合；相邻页有续文和跨页书名，应按连续页组／词条聚组。用某页渲染图训练、再用该页原图测试，会泄漏内容，只能作为注明条件的同内容跨域诊断。

建议将现有 45 页视为开发与合成种子库。内部验证按连续页组隔离；正式泛化测试另补未参与开发的其他书、版本或独立篇章，并独立终校。不要把同书相邻页随机切成训练／测试后宣称跨古籍泛化。

## 6. 建议实施顺序与验收

1. **确定第一版范围**：正文区域、大小字、局部列片段、阅读序、书名框和圈号；目标文字按当前 profile，保留稀有字和 PUA。
2. **先用六页做贯通样本**：@312（标题）、@333（常规正文）、@318（混排／空位）、@328（圈号／合字／空列）、@342（E815）、@349（E701）。导出干净渲染图及标签，并给相同六页补原图区域位置，实际记录人工修正成本。
3. **验收后扩到 45 页**：导出顺序与 TXT 一致、全部非空单元可见、位置无越界、合字和 overlay 无丢失、字体加载可复现；原图部分逐页查看叠框并确认目标内容完整，保留 `proposed/reviewed` 状态。
4. **再做效果对照**：同一模型／训练预算下比较原图训练、合成训练、合成加原图适配；在隔离的真实扫描验证页上报告正文 CER、区域检测指标、阅读顺序错误和复杂版式分项。初校与终校结果分开，不能把文件一致性检查视为模型准确率。

实施前无需再次重做整套转写系统。主要新增工作是图像导出与标签规范，以及真实扫描图的定位和复核。推荐先让方案 2 建立自动监督链路，再用方案 1 校验并改善实际扫描效果。

若后续对外分发，还需单独确认扫描图与随附字体的再分发／训练使用许可；本次没有进行授权调查。
