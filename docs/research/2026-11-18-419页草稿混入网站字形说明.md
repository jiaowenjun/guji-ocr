# 419 页草稿混入网站字形说明

记录日期：2026-11-18。状态：**已确认，未修复，暂缓处理**。用户要求先记录，供后续参考；目前尚无经过验证的通用自动剔除方案，不代表此问题无法解决。

## 现象与预期

第 419 页「伉」条生成草稿时，在正文末尾额外出现：

> 亢字原刻从凡不从几作。

源站转写的最后一段是：

> 【戴侗曰】高亢之亢當作亢。與亢龍之亢同。亢字原刻从凡不从几作。

核对本页扫描图，「伉」条到「與亢龍之亢同」结束，接着进入「伊」条。额外一句属于网站对字形的说明，不应成为刻本正文。预期保留前面的戴侗引文，将网站说明与正文分离。

核查时，已保存的 [`0419.gj`](../../kangxi-gold/annotations/0419.gj) 不含这句话；但用当前代码从来源数据重新生成，仍能复现。因此，**单页稿件已无该句，不等于生成流程的缺陷已修复**。

## 已核实的来源与原因

1. 本地爬取库 `var/crawl/kangxi-crawl.sqlite3` 中，「伉」（U+4F09）的原始 HTML 正文与 `og:description` 均含该句，数据库 `text_paragraphs` 也包含它。不是 OCR 新增的文字。
2. v2 解析得到一张卡片，正确选中 `0000s/0419-01-00323-4F09.svg`，结果为 `selection_status=selected`、`text_origin=og_slice`、`attached_segments=[]`。旧记录按需重解析后仍复现，不是旧解析缓存未升级。
3. 该句与戴侗引文直接相连，处于同一正文段，没有独立标签、其他词条卡片或「考證：」栏标识。当前 [`_split_attached()`](../../tools/crawl/kangxi_entry_parser.py) 只拆分有其他卡片佐证的附带子段及独立考證材料，因此保留整段。
4. [`_draft_bands()`](../../tools/dataset/kangxi_page_tool.py) 将选中卡片的 `text_paragraphs` 收入草稿。整页 OCR 尾裁只确定页面末界；该句位于「伉」与「伊」之间，后面还有真实正文，故不会被页尾裁剪删除。折行与大列重组也不负责删除页中字符。

来源页面：[「伉」详情](https://www.kangxizidian.com/search/index_v.php?stype=Word&sword=%E4%BC%89&detail=y)。以上证据来自本地缓存，没有重新抓取网站。

扫描图：`/Volumes/WD-2T/guji-ocr/raw/kangxizidian/pages/0419.jpg`；SHA-256：`841eee5a6820173cc25c1d0aa73528572f1be71f0a2548cad778a1b77bcf131f`。对应整页 OCR 缓存为 `var/ocr-cache/0419.json`，也不含该句。

## 暂缓原因与后续参考

这是**同一卡片内的网站附注混入正文**，不属于已修复的跨卡片释文混入。当前 HTML 没有可直接利用的独立结构边界，仅拆卡片无法解决。

- 不能看到「原刻」「原字」「从某」就统一删除：刻本本身也可能包含字形分析。
- 不能仅因 OCR 未命中就自动删除：OCR 可能漏掉真实正文；此前评估已经构造出整段漏识导致误删的反例。
- 本页可据原图人工排除该句，但这只能处理单个样例。尚未实现、验证可安全推广的识别与剔除规则。

后续可研究网站附注候选识别、局部图像／OCR 核验及可撤销的删除预览；这些只是待评估方向。本次仅登记问题，不实现过滤规则，不改来源库、OCR 缓存或标注稿。
