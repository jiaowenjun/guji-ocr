# U+2023F〈𠈿〉补录报告

日期：2026-11-19；执行时间：16:31–17:10（Asia/Shanghai）；提交：`55b2436690bfd2ea69aec1d4173328387f15aafa`（字体+证据+初版文档；本行回填见后续 docs 提交）。
规范：按 [字体补录规范](../font-replenishment-spec.md) v1 产出与验收。

## 结论

- **身份／Unicode／是否 PUA**：𠈿 = **U+2023F**（Ext-B 标准码位，非 PUA）。人部 9 画
  （extra 7），仓颉 OLNE；@467 第 4 字头，同页为 ⿰亻X 连码段 U+2023C–U+2023F + 修 U+4FEE。
  身份铁证＝站方 SVG 文件名自带码位映射（`0467-04-00560-2023F.svg`）+ 爬取库词条在册；
  视觉比对仅作字形核验，不用于定码。
- **为什么需要补录**：guji-large 基线（康熙字典體傳承版 v001.014，即站方自家字体）原版
  cmap 即缺此字——同页邻字 U+2023C/D/E 均在库，属 **v14 个案 cmap 缺口**（站方词表已编码
  ≠ 站方字体在库，与 K0000 未编码不同类）。补录前回退链全灭实测（康熙傳承版、HanaMinA、
  macOS Songti/STHeiti/Arial Unicode 全缺；Ext-B 实收于 HanaMinB 而大字栈未列），大字位置
  必 tofu；正文 plane2 原有 `u2023F` 不受影响。
- **写入范围与明确不写入的字体**：仅 `guji-preview-grid/public/fonts/guji-large.ttf`。
  明确不写：plane0/plane2/planef（plane2 已有该字；其余平面按拆分职责不收）、
  `~/Library/Fonts/KX_47043_14.ttf`（与 #8 U+2E85 同边界，系统字体有意不同步）。

## 操作与验证

- **命令与 dry-run**：

  ```sh
  python3 tools/dataset/kangxi_font_patch.py \
    --font guji-preview-grid/public/fonts/guji-large.ttf \
    --svg var/unencoded/kangxi-unencoded/svg/0467-04-00560-2023F.svg --cp 2023F \
    --anchor-svg var/unencoded/kangxi-unencoded/svg/0467-03-00559-2023E.svg --anchor-cp 2023E
  ```

  工具无 `--dry-run` 旗标；其内置顺序＝先在 tmp 上跑 chamfer 验证闸、过闸才 `os.replace`
  原子替换。另做**干跑重放**：补前备份副本重放 `patch_font` 同函数路径，chamfer 复现 0.033，
  glyf/cmap/hmtx/maxp 与生产文件**逐字节一致**，唯一差异 `head.checkSumAdjustment`
  （4 字节字体级校验和自算差，U+2BD6E 先例已知坑）；整文件 sha 因此不逐字节可复现
  （重放 `82315135…`），以表级比对+闸值为准。
- **前后 SHA、字节数、cmap、glyphOrder**：SHA `3973ccbe…`→`447a77da…`；
  46,624,948→46,625,740 B；cmap 49,409→49,410（仅此一增）；glyphOrder 49,412→49,413；
  U+2BD6E、U+2E85 保留；备份＝`font-backups/guji-large.ttf.3973ccbe….ttf`。
- **目标 glyph、bbox、度量、闸值**：`u2023F`，4 轮廓，bbox `[34,-154,987,695]`，
  advance 1024（锚字同值）；字体无 vmtx 表，vmtx 不适用。**chamfer 0.033（闸 0.15，余量
  4.5×；首例 U+2BD6E 为 0.029 同级）**——此为描摹保真回归分，不是字符身份证明。
- **浏览器／渲染／测试／构建**：四层验收明细见
  [patch-verification.json](evidence/u2023f/patch-verification.json)——
  三视图目视（[comparison.png](figures/u2023f/comparison.png)）同构无描摹缺陷；
  dev server 以新缓存戳 200 供应新字体（46,625,740 B），应用页注入同栈 96px 元素
  `document.fonts.check('20px "GujiLarge"','𠈿')`=true、渲染刻形非 tofu
  （[browser.json](evidence/u2023f/browser.json) + [browser-verify.png](figures/u2023f/browser-verify.png)）；
  vitest 1138/1138（含并行 WIP）、`npm run build` 通过且 dist 字体哈希与生产一致；
  JSON 校验、`git diff --check` 通过。

## 限制与回滚

- 已知限制：① @467 未标注，应用内字格暂不显示该字，浏览器验收为同栈注入元素的等价记录；
  ② 站方 v14 对已编码字头存在个案 cmap 缺口（本例 + 歺形区已知缺 5），后续缺字判定一律以
  本地 cmap 实测为准；③ CSS 大字栈补 `HanaMinB` 的兜底建议未随本次执行（全局渲染行为
  变更，待用户定夺）。
- 回滚：补前 Git blob（HEAD）+ 按哈希备份 `font-backups/guji-large.ttf.3973ccbe….ttf`。
  本字为此后字体唯一变更时可直接恢复补前文件；已有后续补字时应针对 `u2023F` 做单字移除
  并重跑保护检查（spec §7），同步撤销缓存戳、Changelog、登记簿条目。
