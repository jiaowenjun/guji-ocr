# OCR 整页 vs 大列裁剪：对比测试分析报告

日期：2026-11-14
测试集：kangxi-gold 初校 23 页（@312–328、@330–335，status=first）
证据数据：[evidence/2026-11-14-ocr-column-vs-full.json](evidence/2026-11-14-ocr-column-vs-full.json)（含逐页 cov/prec 明细）
上游工具：[tools/eval/kangxi_column_seg.py](../../tools/eval/kangxi_column_seg.py)（先验网格列分割）

## 1. 背景与目的

列分割（8 大列/16 小列先验网格）已稳定落地。本实验回答：**用列分割结果把整页拆成 8 张大列裁剪图分别 OCR，与整页 OCR 相比识别质量如何**——即列分割除可视化外，能否反哺识别本身。

## 2. 实验设置

| 项 | 说明 |
|---|---|
| 引擎 | PaddleOCR-VL-1.6（本地 paddleocr-baseline :8010 代理 aistudio） |
| 整页 | 既有 `var/ocr-cache/NNNN.json` 缓存（零新成本） |
| 大列 | 每页按 `segment()` 的 majors[8] 裁剪（block 的 y 范围内，x±2px），JPG q92，共 **184 张** |
| 提交 | 逐列单 job（服务 API 一图一 job，无单请求多图），并发 3→6，约 10 分钟；5 列真空重试确认仍空 |
| 清洗 | **只保留 CJK**（`[\u3400-\u4dbf\u4e00-\u9fff U+20000-U+3ffff \uf000-\ufaff]`）——裁剪图 OCR 会输出 markdown 表格/HTML `<img>`/拉丁注音等装饰语法，@327 原始输出 737 字≈2× 金标全是这类噪声；两侧同口径 |
| 对齐 | SequenceMatcher 归一化对齐（与 eval_ocr_fold 同口径），金标取 .gj 全部行按阅读序拼接 |
| 指标 | cov = 匹配字数/金标字数（覆盖）；prec = 匹配字数/OCR 字数（准确）；**得分 = 10×F1** |

## 4. 关键发现

### 4.1 准确率：裁剪普遍提升（17/23 页 prec 反超）

裁剪消除了邻列笔画渗透、版心/页眉噪声与跨列误读，**prec 在 17/23 页反超整页**，最大提升 @334 **80.4→93.2**（+12.8pt，未编码字+带圈标最密页）、@326 94.4→97.7、@330 92.4→97.8、@312 92.8→96.1、@322 90.4→96.7。反超幅度与版式复杂度正相关：越脏的页，裁剪提纯越明显。

### 4.2 覆盖率：整页全面占优，裁剪掉分两大机制

- **真空列**（5 处：315:7、316:5、322:4、326:3、334:4）：纯大字/稀疏变体列，VL 对裁剪图无输出（重试确认），如 @327:5 整列只认出『川』。整页识别时这些内容并入邻列反而能认出。
- **窄高图漏识**：~120px 宽的裁剪图上 VL 偶发整段漏行——@335 cov 69.3、@316 77.5、@328 77.1、@322 79.8、@327 80.4，全部是变体/字头密集页的左侧大列。

### 4.3 胜负画像

- **列胜页恰是全库最难版式**：@334（#□ 占位+带圈标最密）、@312（一部起始、右半字头大字区）——脏版式下「裁剪提精度」压倒「裁剪丢覆盖」
- 纯正文页两者 97–99% 等效（@314/325/332/333）；常规混合页整页小胜（cov 优势 1–4pt）

### 4.4 评估口径的坑（复现必读）

裁剪图版式简单，VL 反而爱输出**装饰语法**：markdown 表格、`<div><img>`（把字头大字当插图，@312:1）、拉丁注音。@327 原始输出 737 字 vs 金标 341 字，清洗后内容本身正确。**不做 CJK-only 清洗会得出 prec 33–65% 的假象**（首轮未清洗时大列均值仅 8.36，清洗后 9.21）。

## 5. 结论与建议

1. **裁剪提精度、整页保覆盖**，纯整页仍是当前默认的正确选择（均值 −0.31，且省 8 倍 job）。
2. **混合策略是明确的潜在改进**（未实施）：以大列裁剪为主、对真空列/低覆盖列回退整页识别的对应文段拼接；@334 类页面预期可拿到 9.3+ 而非 8.3。
3. 工程事实：服务 API **一图一 job**（无单请求批量），并发 8 提交墙钟≈单 job；裁剪图结果须取 `result.json.result.layoutParsingResults[0].markdown.text`（顶层 `markdown` 字段常为空）。
