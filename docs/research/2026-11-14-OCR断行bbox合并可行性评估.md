# OCR 自动断行：bbox 合并可行性评估

日期：2026-11-14
测试基准：kangxi-gold 初校 23 页（@312–328、@330–335，status=first）
证据数据：[evidence/2026-11-14-ocr-bbox-fold-feasibility.json](evidence/2026-11-14-ocr-bbox-fold-feasibility.json)
评估工具：[scripts/eval_ocr_fold.py](../../scripts/eval_ocr_fold.py)（本次入库，可回归复跑）

## 问题

OCR 自动折行（`ocr_fold_page_lines`）以 PaddleOCR-VL markdown 的空行分组为物理行界。此前的 25 页初校真值对照显示组界 91.5% 为真行界，但残留**过分裂**：一个物理行被拆成多个组（插入多余的换行）。两个核心问题：

1. OCR 结果是否带有 bounding box 坐标信息？
2. 能否用 bbox 几何（同列纵向堆叠）把多个 box 识别为同一大行，修复过分裂？

## 问题一：OCR 结果有没有 bbox？

| 输出层 | bbox 粒度 | 结论 |
|---|---|---|
| PaddleOCR-VL-1.6（现行缓存） | 布局**块**级：`prunedResult.parsing_res_list[].block_bbox`，每页仅 7 块，整页正文是**一个** `vertical_text` 块盖满版心 | 无行级坐标；markdown 行只有顺序没有位置 |
| VL + `optionalPayload {"useLayoutDetection":false}`（实测） | 退化为单个 `ocr` 块，全文行拼在一块 | 仍无行级坐标 |
| **PP-OCRv5（同一 aistudio job API，`model=PP-OCRv5`，实测）** | **行级** `rec_boxes` / `rec_polys` / `dt_polys` / `rec_texts` | ✅ 可用，~10s/页；竖排列检出为细高框（w≈60–110，h≈300–1600） |
| 扫描图直接投影（零 OCR） | 列网格 | ✅ 本版刻本**无界行**（只有边框线），但列间隙呈墨迹剖面谷值（~60–70px 间隔），可确定性检测列位置与每列墨迹纵向范围 |

## 问题二：bbox 合并同列多框——三条路线实测

以初校 23 页金标 .gj 物理行为真值，每个 VL 组界计算混淆矩阵（真界误删 = 合并规则删掉了真实行界；假界修复 = 正确合并了过分裂）。

### 基线（现状，不做任何合并）

- 金标物理行 460，VL 组 593，组界 570（可映射 509）
- **可映射组界 94.3% 为真行界**（480/509）；过分裂 29 处——**19 处集中在 @320 一页**（增字头+变体密集的部首页），其余 8 页各 1–2 处
- 漏折 13/460（VL 把两行并成一组；bbox 只能合并、无法补拆，对此无用）

### 路线 A：PP-OCRv5 行框 + 文本流对齐 + 同列判定（配对法）

v5 框按槽位排序成阅读流，相邻框配对判同列（框心差 < 0.72·pitch 且纵向衔接）；VL 组界经归一化对齐映射到流位置后按配对类别决定合并。页级门槛：VL↔v5 文本对齐覆盖 ≥50% 才启用（**12/23 页达标**——v5 古字识别太差，半数页对齐不可信）。

**结果：真界误删 44 / 假界修复 12** —— 净负 3.7:1。

### 路线 B：v5 框装配成列 + 容量区段 DP

框贪心装配成列（cx 相近且纵向邻接），每列容量 = 跨度/字高；VL 组按阅读序单调分配到列（区段 DP，全局调参扫描）。

**结果（最优参数）：真界误删 197 / 假界修复 67** —— 净负 3:1。

### 路线 C：扫描图列网格投影 + 容量 DP（最稳几何源）

列网格由墨迹投影谷值确定（不依赖任何 OCR det），每列容量按墨迹纵向范围估算。@333 上网格 **16 列 = 金标 16 行全中**，且列高差异（1510 vs 1573）正确反映真短行——网格本身是可靠的。

**结果（调参最优 under=0.1/over=2.0/slack=4.0/empty=0.3/drop_pen=0.4）：真界误删 159 / 假界修复 81** —— 仍净负 2:1。

## 否决根因：金标行 ≠ 物理列（结构性冲突）

三条路线一致净负不是调参问题，而是**目标错位**：

- 变体/增字头区，人工初校**特意把一个物理列拆成多条 .gj 行**。实证 @327 lines 18–21：

  ```
  【玉篇】古文
  不字。註詳
  三
  畫。
  ```

  这是**同一个视觉列**里的四行金标。版式（图像核实）：变体大字居一列、出处/释义小字各占独立窄列，大字+小字注同列叠放。

- 「同列即合并」必然摧毁这类真行界——与已移除的 `<8 合并规则`（实测删掉的组界 63% 是真界）**同一族失败**，只是判据从文本长度换成了几何。
- 附带发现：v5 det 质量页间波动剧烈（@333 23 框干净；@313 重叠错位+空文本框；@320 跨列宽扁框），行框证据本身不可靠。
- 漏折信号也不成立：组数−列数在漏折页无区分度（变体区窄列网格检不出，列数系统性低估，@327 网格 14 vs 金标 28 行）。

## 结论与建议

1. **bbox 同列合并：不实施。** 几何上「同列判定」可行（列网格可确定性检测），但初校行语义包含「列内视觉断口拆行」，合并不是校对者想要的操作；全部实测变体净负。
2. **维持现状**：VL 行组界（94.3% 精度）继续作为折行信号。过分裂的代价已被设计封顶——折行只插换行、永不改字，多余断点在对照视图中可见即删（拖动即可）；漏折补行才是隐性成本，而 bbox 对漏折同样无解。
3. **唯一值得做的后续**：过分裂 19/29 集中在 @320 型增字头页。可识别该页型（字头多、短组密集）后在编辑器给「建议人工折行」提示，而不是自动合并。
4. **沉淀资产**：
   - `scripts/eval_ocr_fold.py`：初校真值 × OCR 组界回归评估（此前历次对照均为会话内临时脚本，本次正式入库）；
   - `scripts/kangxi_column_seg.py`：分层列分割（大列=两小列/大字列宽段 → 小列，含每列墨迹范围/容量/字峰数，`--draw` 出标注图）——列网格投影的正式实现；
   - PP-OCRv5 行级 bbox 通道确认可用（同一 job API 换 model 即得），供后续版式研究。

### 列分割实测（2026-11-14，`scripts/kangxi_column_seg.py`）

- 版式像素实测：**小列 ≈ 60px、~24 字/列（字步进 ≈ 列距 ≈ 59px）；一条金标行 = 一个小列**（@333 每小列字峰 23 = 金标行字数）；字头大字列 ≈ 2× 小列宽、内部无谷，天然是大列对齐锚点；本版**无界行**，列界靠墨迹剖面谷值。
- **先验约束 v2（用户给定：每页必有 8 大列 16 小列，各页列宽大致相同）**：17 条等距网格线 2D 拟合（pitch × 右缘，多页运行时 pitch 域取全体页池化中位 ±3px）+ 谷值 ±5px 吸附；谷值只做对齐证据、不做存在依据——变体区漏谷的小列由网格补出（`bound: detected|grid` 分级标注证据）。全部 24 页稳定输出 **8 大列/16 小列**，pitch 落 58.6–61.4（先验「各页宽度大致相同」获数据验证）。
- VL 正文块 bbox 会整页漏检半页（@312 宽 635、@330 宽 898 vs 框内 ~950+）：**版框线投影检测兜底**（左线被裁时按先验宽回推），各候选块跑网格拟合按谷值证据仲裁、平局信 VL。
- **版心鱼尾栏修复（2026-11-14 二轮，@323 报障，提交 e33b624）**：版框取最外线会把版心（魚尾+部首名+书名，@323 在 x 1023–1117）圈进块、首槽落在魚尾上；且版心边缘也产生锐利谷值，证据仲裁会被「网格右移一槽」的解反超（13:11）。修复三层：① 线簇**配对宽度最接近 16×pitch 的框**、原始簇极值对也入候选（@330 真右线 1041 恰是外线）；② **VL 完整（宽≈先验±半列）时直接采用 VL、不引入框**——VL 从不含版心，框只为补救 VL 漏检（漏字头大字区）而设；③ 魚尾（上部带内实心黑块）右缘以内的框候选排除。物理判据穷举记录（均不可用）：版心槽墨迹全高稀疏（邻列渗透令跨度/密度失效）、魚尾线描非实心（列墨迹仅 0.12–0.45）、纵向均匀性 CV 与字头大字列同型（1.4）。结果：@323 评分 5.50→**9.75**（slot0=金标首行 est24↔23 字）、@330 恢复 60.5/ev13，23 页均值 7.74→**8.02**。
- 效果：@333 逐列 `chars_est/cap=23/24` 与金标逐行吻合；@327/335 变体短列容量紧贴真实（`4/5`、`9/10`，v1 里虚高为 17）；字头大字列标 `wide` 且 chars_est 显著小（每半槽 3–5 峰）。残留：变体槽边缘受邻列笔画渗透，y 墨迹范围偶偏满列（cap 虚高），信任度看 `bound` 与 `chars_est`。

### 列分割逐页验证（2026-11-14，`scripts/eval_column_seg.py`）

方法：金标行按阅读序经 DP 单调分配到 16 小列（允许首/尾空列=金标未转写的字头/前部尾区），按列残差评分；wide 字头列单独容差（chars_est 对大字/竖笔画结构性不可靠）。23 初校页结果：

|---|---|---|---|---|---|---|---|
| @312 | 7.75 | | @320 | 7.75 | | @328 | 6.50 |
| @313 | 9.00 | | @321 | 6.25 | | @330 | 6.50 |
| @314 | **10** | | @322 | 6.00 | | @331 | 8.50 |
| @315 | 9.00 | | @323 | 5.50 | | @332 | **10** |
| @316 | 8.00 | | @324 | 8.00 | | @333 | **10** |
| @317 | 6.25 | | @325 | **10** | | @334 | 8.00 |
| @318 | 9.25 | | @326 | 8.00 | | @335 | 5.50 |
| @319 | 6.25 | | @327 | 6.00 | | | |

均值 7.74 / 中位 8.00；满分 4 页（@314/325/332/333，全部是「金标 16 行=16 小列 1:1」纯正文页，覆盖列字数偏差 ≤0.8%）；好列率 79.7%（好+近 90.8%，360 受测列）。

结论：① **几何分割本身几乎全对**——坏列无「相邻列 +r/−r 成对」的边界位移特征，列位无系统性偏移；② 失分三大机制全是 `chars_est` 字峰计数器问题而非列位问题：**引用偏置**（书名框【】每框计 1 峰而金标归一化剔除，引用密集页每列 +3~5，@323/319/317/321 系统拉低）、**竖笔画/大字字头**（丨、变体大字 glyph 破坏峰计数，@330/@328）、**变体小字堆叠渗透**（@327/335）；③ 提分方向：chars_est 剔除窄峰（【】宽≈0.3 字宽）或正文列以 cap 为准（cap 24 ≈ 金标行字数）。
