# 402 页草稿多余释文自动剔除评估

日期：2026-11-18。范围：当前代码、已缓存详情页 HTML、整页 OCR、用户提供的 402 页初校文本，以及清单中的 89 个 `first` 页。

后续扩展：[初校非空页全量评估](2026-11-18-初校非空页草稿冗余全量评估.md)检查了更新快照中的 74 个非空初校页，补充同码位多卡片、网站说明、引文移位等情况；本文保留 402 页开发实验的原始范围。

**结论：可以自动提出这类删除区间。402 页仅用现有 OCR 就能准确找出两段共 457 字；进一步检查发现，源站 HTML 还保留了「仅／僅」「仆／僕」的区分，优先修复采集层能更直接地消除本例的问题。建议采用“源站词条拆分＋OCR 范围核验”，先提供可撤销的删除预览。**

本次新增只读评估脚本和证据，未修改采集器、草稿生成流程、数据库、OCR 缓存、`.gj` 或 manifest。402 页虽然已有用户初校内容，当前 manifest 仍标记为 `draft`，因此单独作为定向样本，不混入 89 页初校回放。

## 1. 本例的原因可以定位到采集层

[`fetch_kangxi_entry.py`](../../tools/crawl/fetch_kangxi_entry.py) 的 `parse_detail()` 用 `og:description` 生成 `text_paragraphs`，用全 HTML 上的首次字段匹配取得字头和页位。对同一查询下的多个字形卡片，这会把合并的释文挂在第一个字头上。

已缓存的 HTML 有以下明确证据：

| 查询 | 第一张卡片 | 另一张卡片 | 需要处理的结构 |
| --- | --- | --- | --- |
| 仅 | 仅，武英殿本 402 页第 4 字 | 僅，510 页第 3 字 | 「仅」卡片正文里还有一个以 `（僅）` 开头的附带子段，内容与「僅」卡片相同 |
| 仆 | 仆，402 页第 5 字 | 僕，514 页第 1 字 | 两张卡片正文各自独立；`og:description` 将它们拼接 |

所以，**只改成读取第一张 HTML 卡片，对「仆」有效，对「仅」仍不够**；还需要识别并保存明确指向其他字形卡片的附带子段。不能把任意括号内文字当成可删标记。

只读提取实验按缩略图文件名中的码位选择卡片，再对「仅」核实 `（僅）` 后的内容与另一个卡片完全一致，得到：

- 「仅」本条 25 字，附带「僅」释文 45 字；
- 「仆」本条 57 字，另卡「僕」释文 412 字。

这两段选中正文与 402 页初校中的对应词条一致。该结论只覆盖本次核查的两个 HTML，不代表已验证全站所有模板。元数据也应按卡片读取：例如当前「仆」记录的古文 `䑑` 实际出现在「僕」卡片上。

## 2. 现有草稿流程为什么没有剔除

[`kangxi_page_tool.py`](../../tools/dataset/kangxi_page_tool.py) 中的链路为：

```text
前页续文 → _draft_bands 全量词条组装
         → _trim_bands_to_page 整页尾裁
         → ocr_fold_page_lines 折行
         → ocr_regroup_bands 大列重组
```

尾裁只确定整页最后一个字符的位置，保留此前全部内容。本例的两段多余释文处在「仅→仆」「仆→仇」之间，后面还有真实正文，尾裁自然不会删除。折行和重组也不负责删除字符。

重放当前流程的整页尾裁确实执行了，但只删去「仇」条溢出页尾的部分；这与页中混入其他词条是两个独立问题。页中剔除应插在折行、重组之前，并单独记录来源及删除区间。

## 3. OCR 实验及计数

计数去掉标点、空白、`.gj` 的 `@页码`、`#`、`*` 和注释；保留字头汉字；OCR 去掉末尾页缘邊題。按 Unicode 字符计数，不进行繁简、异体或 OCR 错字替换。这是文本长度，不是版面的占格数。

| 文本 | 字数 |
| --- | ---: |
| 现有尾裁后的 402 页草稿 | 811 |
| 整页 OCR 正文 | 356 |
| 初校正文 | 354 |
| 自动提出删除的两段 | 457 |
| 删除后的草稿 | 354 |

删除区间：

| 字头 | 保留到 | 删除的起点与终点 | 删除字数 |
| --- | --- | --- | ---: |
| 仅 | `又【集韻】與帑同。` | `【唐韻】【集韻】【韻會】渠吝切…` 至 `又劣也。` | 45 |
| 仆 | `【正韻】𠀤敷救切，否去聲。頓也。` | `【唐韻】【集韻】【韻會】𠀤蒲沃切…` 至 `入降廉猶臣僕。` | 412 |

**删除后的归一化字符流与初校逐字一致，正文误删为 0。** 这不表示标点、空位和折行已经自动初校完成。预测时未读取本页初校内容；初校仅用于事后比较，前页初校仍由既有续文流程使用。规则是在已知 402 页问题的情况下设计的，402 是开发样本，不能当作独立准确率测试。

### 为什么不能直接删除整页 diff 中未匹配的片段

OCR 的局部阅读顺序与 `.gj` 词条顺序不同。例如：

```text
木切音支義同 又集韻韻會 仇 唐韻巨鳩切集韻韻會正
正韻叅敷救切否去聲頓也 韻渠尤切叅音求匹也匡
```

「仇」条的前半段出现在「仆」条末段之前。直接 `SequenceMatcher` 顺序对齐会产生一个 423 字的删除块，其中除了真正多余的 412 字，还包括真实正文 `正韻𠀤敷救切否去聲頓也` 的 11 字。「仅」附近同样会把 `韻與帑同` 卷进大差异块。短条「仃」的正文也不能因 OCR 错字和换序而整体删除。

### 本次保守原型的规则

1. 按已知字头拆分草稿，只提出非末字头的释文尾段，保护后续字头；不处理短条整体删除、词条内部挖洞或复杂大字作用域。
2. 查找在草稿和 OCR 中都只出现一次的连续 4 字锚点，允许锚点局部乱序；重复的 `唐韻集韻韻會` 等套话不作为唯一定位依据。
3. 保留段须有足够锚点支撑，最后锚点恰好到句末，拟删尾段至少 20 字；下个字头的前段还须在附近 OCR 中得到支持。
4. 最后检查删后长度与 OCR 长度相差不超过 `max(8, ceil(OCR字数×2%))`。全页字数只是校验，不能决定具体删哪一段。

脚本中的覆盖率、局部窗口和长度容差均为探索参数，不是经过校准的置信概率。实际生产可进一步使用带坐标的 OCR，把比较限制在相应字头之间的页面区域，以减少换序、重复套话及无关命中的影响。

## 4. 回放与误删边界

对清单中 89 个 `first` 页执行只读回放：

- 14 页无有效 OCR 缓存；52 页因复杂字头或作用域被原型跳过；23 页符合草稿实验范围。
- 23 页中，366 页提出一个 80 字候选，但删后仍与 OCR 相差 11 字，未通过 8 字容差；其他页无候选。因此这些页没有实际接受的删除，不能据此证明算法有较高召回率。
- 另外把现有初校稿作为“本来不需要删除”的负对照，其中 15 页符合原型范围，均未接受删除；加上独立的 402 页负对照为 16 页。不能表述为“89 页全量验证无误删”。

还进行了一个人工构造的漏识压力实验：从 402 页 OCR 中移走「仆」条末尾两段共 26 字，输入则使用已经正确的初校稿。原型错误地提出并接受删除对应的 26 字正文，因为此时锚点与字数差会一起支持错误结论。

这说明 **OCR 若漏识整段，文字匹配和字数一致两个条件并不独立**。本反例不代表真实模型漏识的发生率，但排除了“只靠这两个条件就能保证不误删”的结论。OCR 字数通常稳定仍然非常有用，只是不足以独立证明页面没有这段文字。

## 5. 建议实施顺序

**先修复详情页的词条归属，再增加 OCR 辅助剔除。**

1. 将详情页解析为独立卡片，保存各自的字形、码位、缩略图、版本页位、古文和释文。用页面字头索引中的码位／缩略图选择相应卡片。页位表示词条起始页，续文场景须通过既有来源字头匹配，不能要求每页都与起始页相同。
2. 对 `（僅）` 这类有明确字形标记、另卡和相同释文可交叉证明的子段，单独保存其归属。对不明确的括注原样保留。保留原 HTML，并给解析结果加版本，避免代码改好后仍复用旧的合并缓存。
3. 草稿构建完成、折行之前，用 OCR 检查尚未解释的长尾段。保留源文字符，只提出删除区间与证据；OCR 错字不直接覆盖库文。
4. 首版提供删除预览、保留理由、撤销及低置信度回退。高置信度自动剔除应优先限于有源站结构证据的情况；只有 OCR 缺席证据的候选，可按需调用局部 OCR 或图像检查复核。
5. 后续验证分别统计多余文本删去量、正文误删量、拒绝处理量。扩展到其他混合字形、跨页续文、未编码字头和正文中段差异后，再决定自动应用范围。

对 402 页，源站结构和现有整页 OCR 两条路径都能独立定位所需的 457 字，无须为了这页重新跑 OCR。正文内部夹入异文、来源无分段标记等更一般的问题，仍需单独评估。
