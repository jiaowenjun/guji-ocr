# 康熙字典来源卡片与附带子段拆分

2026-11-18 实现。来源解析位于 [`kangxi_entry_parser.py`](../../tools/crawl/kangxi_entry_parser.py)，用于新抓取、添加新页、前页续入、流程回放及详情查询。

源站的 `og:description` 会合并多个字形的释文。例如查询「仆」同时得到 402 页「仆」和 514 页「僕」；直接使用整段转写会把「僕」的释文带进 402 页草稿。现在先确定来源卡片，再使用该卡片对应的转写。

## 选择与拆分规则

1. 从字头 SVG、武英殿本页码及页内序号识别卡片，核对图像身份与卡片页位一致。每张卡片独立保存古文、部首、笔画、双版本页位等信息。
2. 添加页内字头时按「码位＋宿主页位＋SVG」选择唯一卡片。按 SVG 保存预取结果，避免同一码位不同来源相互覆盖。前页续文按字头实际所在的宿主页选择，回溯纯续文页时也沿用该宿主页。
3. 对 HTML 的独立子段，仅在以下证据满足时拆出另条内容：
   - 段首为 `（另一字头）`，整段正文与同一详情页内另一卡片的完整正文一致；允许段首带有该卡片声明的古文。
   - 无字头标记的重复子段，必须与另一个同字头卡片完整对应、归一化后至少 8 字，而且前面已有本卡正文。此规则处理 350／4396 页「𠂳」的重复子段。
4. 独立「考證」栏保存为附带编辑材料。普通括注、没有其他卡片佐证的子段、正文中的引用继续保留；网站说明与引文移位不按关键词自动处理。
5. 将选中卡片的完整正文映射回 `og:description` 的连续区间，沿用原转写的标点和段落。无法完整对应时不采用 HTML 正文，返回原聚合转写并提示待核。

卡片身份无法唯一匹配、页位或 SVG 冲突时，同样保留原聚合转写。由此避免选到“第一张同码位卡片”，也避免 HTML 补遗或损坏标签引入新内容。

## 数据结构与旧缓存

SQLite `entries` 仍以查询码位为主键，无须迁表。`record_json` 保留原有顶层字段，新增：

| 字段 | 含义 |
| --- | --- |
| `parser_version` | 当前为 `2` |
| `cards` | 独立卡片；含字头、`source_svg`、页位、独立元数据及正文 |
| `legacy_entry` | 原聚合记录，供不确定时回退与核查 |
| `selection_status` | `selected` 已选定、`unresolved` 无法安全选定、`legacy` 未识别卡片结构 |
| `selection_note` | 未能选定的原因，添加新页时汇入说明 |
| `source_body_sha256` | 卡片正文 HTML 的哈希，用于追踪来源 |
| `text_origin` | `og_slice` 已完整对应原转写；`unverified_html` 仅保存为证据，不用于生成正文 |
| `attached_segments` | `other_entry` 保存另条字头／SVG／页位／原段落；`editorial` 保存考證材料 |

新抓取直接保存 v2 记录。旧缓存由 `resolve_entry()` 在读取时使用已保存的 `raw_html` 按需重解析；这一步不联网、不回写数据库。缺少 HTML 时沿用旧记录。解析结果使用进程内有限缓存，每次返回独立副本。

后续点击「添加新页」即可使用新规则，无须清库或重抓。开发服务器每次请求都启动 Python 工具，因此无须为此次 Python 修改重启前端。已有 `.gj` 和 manifest 不会因读取或回放而重写；初校页保留人工成果。

## 验收

完整证据见 [`2026-11-18-source-cards-implementation.json`](../research/evidence/2026-11-18-source-cards-implementation.json)。基线与新版使用同一草稿生成流程及本地 OCR 缓存，仅切换旧聚合转写与新来源选择；回放不执行 OCR 请求，不写页面或数据库。字符数忽略排版、空白和标点，不等于文件长度。

| 检查 | 结果 |
| --- | --- |
| 76 个非空初校页（含已标记初校的 402 页） | 13 页正文字符流发生变化 |
| 按条目核对剔除区间与初校正文 | 排除 3,767 个冗余字符；误删初校正文 0，归属不明的删除 0 |
| 402 页 | 「仅」排除「僅」45 字，「仆」排除「僕」412 字；整页 811 → 354 字，处理后字符流与初校一致 |
| 已保存 HTML 的全缓存解析 | 未验证的正文变更 0；正文不变却改变段落／标点的记录 0 |
| 来源解析、草稿生成、续文与查询测试 | 93 项通过，包含 15 项新增来源卡片测试 |

发生变化的页为 316、321、322、331、334、341、345、350、356、360、366、367、402。341 页同时恢复了先前被外来尾文干扰的后续字头，因此剔除字符数按条目区间累计，不用整页净减少量替代。

最终快照时间为 17:01:33（Asia/Shanghai）。工作区同期更新了续文裁剪流程：保留完整续文，与新词条统一组装后裁页尾。本次基线和新版均使用这一流程，相比早一轮 3,144 字的结果，331／个增加 82 字、366／于增加 265 字、367／云增加 276 字，共 623 字，均为其他卡片的释文。它们曾被旧续文预裁截掉，因此不能把 3,767 直接当成前一轮历史草稿冗余总量；两轮的逐条来源判断一致。

此次全缓存快照有 16,405 条记录：16,291 条默认选卡成功、100 条待核、2 条未识别卡片结构、12 条缺少 HTML；其中 162 条正文发生变化。默认待核也包括必须结合宿主页才能消歧的同字头卡片，不能解读为 100 条均无法处理。全库检查验证的是来源映射和保守回退；只有初校样本具备人工正文对照，不能据此宣称全库零误删。

此前完整 Python 测试为 114 项、112 项通过，两个现有失败分别为 `test_ocr_dataset.LayoutContracts.test_short_page_aligns_text_and_book_frames_to_the_right`（带数量预期）和 `test_ocr_dataset.IncrementalContracts.test_review_merge_and_stale_import_are_safe`（`Unknown review IDs`）。替换回本次修改前的页工具后仍复现，未在来源拆分任务中修改。
